## この文書について

この文書は、[要件定義書](https://github.com/nbifrye/glossary-map/blob/5d2f6d226dd5248d83e54175e13fa3f8fb587a51/docs/requirements.md) を満たすための設計判断を記録します。中間形式の項目の詳細な定義は、実装時に JSON Schema と仕様書として別に作成します。

## 計算をビルド時に済ませる

クラスタリングと配置は、すべてビルド時に計算します。閲覧時のブラウザーは計算済みの結果を読み込んで描画するだけで、クラスタリングや配置の計算は行いません。この方式を選んだ理由は次のとおりです。

- 同じデータと同じ URL からは、常に同じ分類と配置を再現できる。ブラウザーごとの浮動小数点演算の違いの影響も受けない
- 計算中に画面の操作が妨げられることがない

この方式では、閲覧者がアルゴリズムの計算条件を変えて再計算することはできません。要件はアルゴリズムの切り替えだけを求めているため、計算条件の変更は扱いません。

## 技術スタック

### サイトの生成

静的サイトの生成には [Astro](https://astro.build/) を使います。選んだ理由は次のとおりです。

- 用語ごとのページをビルド時に HTML として生成できる。JavaScript が動く前から定義と参照を読めるため、初回表示が速く、スクリーンリーダーでも読みやすい
- 用語ごとに実在するページがあるため、URL への直接アクセスに対応するための仕組みを GitHub Pages 上に用意する必要がない
- 既定では JavaScript を出力せず、グラフや検索など必要な部分だけにスクリプトを読み込める
- `security.csp` の設定で、Content Security Policy を `<meta>` 要素として出力できる。GitHub Pages では HTTP ヘッダーを設定できないため、この方式が必要になる

Vite で単一ページアプリケーションとして作る方式も比較しました。この方式では、用語の URL に直接アクセスしたときに表示するための工夫が GitHub Pages 上で必要になり、JavaScript が動くまで定義を読めないため、採用しません。

画面の部品には UI フレームワークを使わず、HTML と CSS の標準機能と、少量の TypeScript で作ります。

### グラフの描画

グラフの描画には [sigma.js](https://www.sigmajs.org/) を、グラフのデータ構造には [Graphology](https://graphology.github.io/) を使います。sigma.js は WebGL で描画し、数千のノードと辺を描画する用途を想定して作られているため、約 2,000 語と約 10,000 件の参照という要件の規模に合います。どちらも MIT ライセンスです。

Cytoscape.js も比較しました。機能は豊富ですが、標準の描画は Canvas 2D で、WebGL による描画は [2025 年 1 月にプレビューとして公開された](https://blog.js.cytoscape.org/2025/01/13/webgl-preview/) 機能です。要件の規模で円滑に操作できるかどうかは、sigma.js の方が見込みが高いと判断しました。

## クラスタリング

クラスタリングには、次の 2 つのアルゴリズムを用意します。どちらも、参照の向きを無視した無向グラフとして扱い、同じ 2 つの用語の間の参照の数を辺の重みとします。

- Louvain 法: モジュラリティを最大化する代表的な手法です。[graphology-communities-louvain](https://www.npmjs.com/package/graphology-communities-louvain) を使います
- Leiden 法: Louvain 法を改良し、用語群の内部が必ずつながっていることを保証する手法です。[networkanalysis-ts](https://www.npmjs.com/package/networkanalysis-ts) を使います

参照の向きを考慮する Infomap も候補にしました。しかし、JavaScript から使える公式実装 ([@mapequation/infomap](https://www.npmjs.com/package/@mapequation/infomap)) のライセンスは GPL-3.0-or-later です。このライセンスはリポジトリ全体のライセンスに影響するため、採用しません。参照の向きは、次に述べる階層配置で捉えます。

## 配置

配置には、次の 3 つのアルゴリズムを用意します。

- ForceAtlas2: 参照でつながった用語どうしを近づけ、全体の構造を示す力学的な配置です。[graphology-layout-forceatlas2](https://www.npmjs.com/package/graphology-layout-forceatlas2) を使います
- 用語群別の配置: 選択したクラスタリングの結果に従って用語群ごとに領域を割り当て、その領域の中で ForceAtlas2 を適用します。用語群のまとまりを識別しやすくするための配置です
- 階層配置: 参照元の用語を上に、参照先の用語を下に置き、参照の流れを上から下への向きとして示す配置です

用語群別の配置はクラスタリングの結果を使いますが、クラスタリングと配置はそれぞれ独立して選択できます。ビルド時には、2 通りのクラスタリングの結果と、4 通りの配置の結果を計算します。配置の結果が 4 通りになるのは、ForceAtlas2 と階層配置はクラスタリングによらず 1 通りずつ、用語群別の配置はクラスタリングごとに 1 通りずつ計算するためです。

### 階層配置

階層配置には、Sugiyama 法に基づく [@dagrejs/dagre](https://www.npmjs.com/package/@dagrejs/dagre) (MIT ライセンス) を使います。Sugiyama 法は、次の手順でノードを層に並べます。

1. 循環を取り除く: 用語集には、2 つの用語が互いを参照する場合など、参照の循環があります。循環があると上下の順序を決められないため、一部の辺の向きを一時的に逆にして循環をなくします
2. 層を割り当てる: すべての辺が上の層から下の層へ向かうように、各用語の層を決めます
3. 層の中の並び順を決める: 辺の交差が少なくなるように、各層の中で用語を並べ替えます
4. 座標を決める: 並び順を保ったまま、各用語の座標を決めます

手順 1 で向きを逆にした辺も、描画では本来の向き (参照元から参照先へ) で示します。そのため、循環の一部になっている参照は、下から上へ向かう矢印として表示されます。

約 2,000 語と約 10,000 件の参照に対して dagre がビルド時の計算時間の目標値を満たせるかどうかは、実装時に試験用の用語集で確かめます。満たせない場合は、[elkjs](https://www.npmjs.com/package/elkjs) の階層配置に切り替えます。elkjs は EPL-2.0 と GPL-3.0-or-later のデュアルライセンスのため、EPL-2.0 を選んで利用します。

## グラフの計算

用語集ごとに、用語をノード、参照を辺とする有向グラフを作ります。同じ用語から同じ用語への参照が複数ある場合は、1 本の辺にまとめ、辺にはまとめたすべての参照を対応付けます。自分自身への参照は、グラフの辺にはせず、詳細の一覧にだけ表示します。

クラスタリングと配置の乱数には、決まった値で初期化した疑似乱数生成器を使い、ノードは常にスラッグの順に処理します。ForceAtlas2 の反復回数も固定し、時間ではなく回数で計算を打ち切ります。これにより、同じデータからは常に同じ結果が得られます。

周辺グラフは、選択した用語と、その参照先・参照元の用語から成り、これらの用語の間の辺をすべて含む部分グラフです。用語群は全体グラフで計算した結果をそのまま使い、全体グラフと周辺グラフで用語群の区別が変わらないようにします。配置は、選択した配置アルゴリズムを部分グラフに適用して求めます。全体グラフと同じ理由で、配置の結果は用語ごとに 4 通りになります。計算した配置は用語ごとの JSON に出力し、その用語を選んだときにだけ読み込みます。

## 中間形式

中間形式は JSON で保持し、JSON Schema で形式を定義します。

### ファイルの構成

用語集ごとにディレクトリを作り、用語ごとに 1 つの JSON ファイルを置きます。用語ごとにファイルを分けることで、プルリクエストで訳文を査読するときに差分を読みやすくします。

```text
glossaries/
  sp800-63-4/
    glossary.json
    terms/
      authenticator.json
      ...
```

`glossary.json` には、用語集の情報と、参照と判定する基準の一覧を記録します。基準ごとに ID と説明を持たせ、各参照からは基準の ID で参照します。用語集をまたぐ参照を将来追加できるように、用語集にも一意の ID を持たせます。

### 定義の原文と訳文

定義の原文と訳文は、許可した構造だけを持つ木構造で表します。ブロックは段落とリスト (番号付き・番号なし)、インラインは文字列・強調・リンクに限ります。HTML の文字列は保持しないため、描画時に原文を HTML として解釈することはありません。1 つの見出しに複数の定義が掲載されている場合に備えて、定義は配列にします。

### 用語の URL

用語の URL には、見出しから決まった規則で作るスラッグを使います。見出しを Unicode の NFKC で正規化して小文字にし、`a`〜`z` と `0`〜`9` 以外の文字の並びをハイフン 1 つに置き換え、先頭と末尾のハイフンを取り除きます。スラッグは見出しだけから決まるため、見出しが変わらない限り URL も変わりません。スラッグは用語のファイル名にも使います。スラッグが空になった場合や、同じ用語集の中でスラッグが重複した場合は、検証で失敗とし、取り込みの段階で解決します。

### 参照と根拠

参照は、定義の原文の木構造には埋め込まず、用語のファイルにある参照の一覧に記録します。原文を原典のとおりに保ち、原文のハッシュ値が参照の修正の影響を受けないようにするためです。各参照には、参照元の定義、参照先の用語、根拠となる原文中の表現とその位置、判定した基準の ID を記録します。

位置は、定義の原文から構造を除いた文字列の中での開始位置と終了位置とし、Unicode のコードポイント単位で数えます。参照先は、用語集の ID とスラッグの組で表します。最初のバージョンでは、同じ用語集の中の用語だけを参照先にできます。

### 訳文と原文の対応

各訳文には、対応する原文のハッシュ値を記録します。定義の訳文では、原文の木構造を決まった規則で JSON に変換した文字列の SHA-256 をハッシュ値とします。見出しの訳文では、見出しの文字列の SHA-256 をハッシュ値とします。原文を修正してハッシュ値が変わると、古い訳文として検証で検出できます。

## 画面構成

### ページと URL

サイトには次のページを用意します。

- トップページ (`/`): 収録している用語集の一覧を表示する
- 用語集のページ (`/<用語集の ID>/`): 全体グラフ、用語の一覧、用語群の一覧、原典の情報、参照と判定する基準の説明を表示する
- 用語のページ (`/<用語集の ID>/terms/<スラッグ>/`): 用語の詳細と、全体グラフまたは周辺グラフを表示する

表示モードとアルゴリズムは、クエリーパラメーター (`view`・`cluster`・`layout`) で表します。用語を選んだり表示モードを切り替えたりすると、History API で URL を更新し、ページ全体を読み込み直さずに表示を切り替えます。これにより、グラフを描画し直さずに済み、拡大率や表示位置も保てます。ブラウザーの「戻る」「進む」では、URL から表示を復元します。

### 画面の配置

用語集のページと用語のページは、グラフの領域と詳細の領域で構成します。広い画面では、2 つの領域を左右に並べます。狭い画面では縦に並べ、グラフの領域には周辺グラフだけを表示します。

### 検索

検索欄では、見出しと見出しの訳文を対象に、部分一致で用語を探します。入力と見出しは、どちらも NFKC で正規化し、大文字と小文字を区別せずに比較します。検索に使う索引は、ビルド時に用語集ごとに作成します。

## 性能の目標値

性能の目標値を、次のように定めます。計測には、約 2,000 語と約 10,000 件の参照を持つ試験用の用語集を自動で生成して使います。計測する環境は、GitHub Actions の標準の Linux ランナー上の Chromium とします。このランナーには GPU がなく WebGL をソフトウェアで描画するため、一般的な PC よりも厳しい条件で計測することになります。

- 初回表示: 用語のページの Largest Contentful Paint が 2.5 秒以内であること
- 全体グラフの表示: ページの読み込みを始めてから、全体グラフを操作できるようになるまでが 3 秒以内であること
- 操作時の応答性: 拡大・縮小・平行移動・ノードの選択の間に、50 ミリ秒を超えるメインスレッドのタスクが発生しないこと。用語の選択や表示の切り替えの Interaction to Next Paint が 200 ミリ秒以内であること
- 計算時間: 1 つの用語集のクラスタリングと配置の計算が、ビルド時に 60 秒以内に終わること
- データ量: 1 つの用語集のグラフのデータが、gzip で圧縮して 1 MB 以内であること
