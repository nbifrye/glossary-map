## プロジェクト名

Glossary Map (`glossary-map`)

## プロジェクトの目的

このプロジェクトは、仕様書などの文書 (以下、原典) に含まれる用語集 (Glossary) を対象に、各用語の定義と、定義中に登場する用語への参照を示す静的サイトを作ります。特定の文書に限らず、任意の用語集を収録できる汎用的な仕組みにします。最初のバージョンでは、[NIST SP 800-63-4](https://pages.nist.gov/800-63-4/) を構成する 4 つの文書 (SP 800-63-4・SP 800-63A-4・SP 800-63B-4・SP 800-63C-4) の用語集を、文書ごとに 1 つずつ、合わせて 4 つの用語集として収録します。

各用語について、定義の原文、見出しと定義の日本語の訳文、原典の情報を提示します。また、各用語の定義が参照している用語 (参照先) と、各用語を定義中で参照している用語 (参照元) を、根拠とともに確認できるようにします。参照を全体グラフと周辺グラフで俯瞰し、参照が密な用語群を発見して探索できるようにします。主な利用者は運営者自身ですが、サイトは一般に公開します。

## 機能要件

- 1 つのサイトに複数の用語集を収録し、用語集を切り替えて閲覧できる
- 用語の見出しおよび見出しの日本語の訳文で検索できる
- 各用語について、見出しの訳文と、定義の原文・訳文を確認できる
- 各定義について、原典の該当箇所へのリンクがある場合はリンクから開くことができ、リンクがない場合 (PDF など) は原典内の記載位置 (章・ページ番号など) を確認できる
- 用語集ごとに、原典の書誌情報 (名称・バージョン・公開日・URL・取得日) を確認できる
- 選択した用語について、その用語の定義が参照している用語 (参照先) と、選択した用語を定義中で参照している用語 (参照元) の両方を一覧で確認できる
- 定義の原文中の参照箇所から、参照先の用語へ移動できる
- 各参照について、根拠となる原文中の表現・その位置・参照と判定した基準を確認できる
- 用語集ごとに、参照と判定する基準の説明を確認できる
- 用語集内のすべての用語と参照を、参照元から参照先への向きを区別できる 1 つの全体グラフとして俯瞰できる
- 全体グラフと周辺グラフ (選択した用語と、その参照先・参照元の用語を含むグラフ) を切り替えられる
- グラフを拡大・縮小・平行移動でき、ノードをドラッグして自由に配置できる。ドラッグで変更した位置は一時的なものとし、共有 URL には含めない
- グラフ上のノードを選択すると対応する用語の詳細を表示でき、線を選択するとその線に含まれるすべての参照の根拠 (1 本の線に複数の参照がまとまる場合を含む) を確認できる
- 参照が密な用語のまとまりとして自動検出された用語群をグラフ上で区別して表示し、各用語群を構成する用語と、用語群内の相互の参照を探索できる
- クラスタリングアルゴリズムと配置アルゴリズムをそれぞれ 2 種類以上用意し、それぞれ独立に選択・切り替えて分類結果と配置結果を比較できる (複数の結果を並べて同時に表示することは必須としない)
- グラフから得られる情報 (用語・参照・所属する用語群) を、グラフ以外の一覧でも確認できる
- 選択した用語集・用語・グラフの表示モード (全体グラフ・周辺グラフ)・クラスタリングと配置のアルゴリズムを URL で共有でき、URL への直接アクセスとブラウザーの「戻る」「進む」で復元できる
- 表示される参照は、概念上の必須の依存関係や推奨される学習順序を示すものではないことを画面上に明示する
- 用語群は自動的に算出された結果であり、原典の公式な分類ではないことを画面上に明示する
- 訳文が非公式であることの注意書きは画面上に表示しない

## 非機能要件

- 用語集は、用語集・原典 (書誌情報を含む)・用語・定義・訳文・参照・根拠を表す共通の中間形式で保持し、定義の原文と訳文は段落・リスト・強調・リンクの構造を保持する
- リポジトリには原典の形式ごとの変換処理を持たせず、中間形式の仕様・中間形式の検証ツール・AI エージェント向けの取り込み手順を用意する。新たな用語集をリポジトリへ取り込むときは、AI エージェントが取り込み手順に従って原典を中間形式へ変換する
- 参照と判定する基準は用語集ごとに取り込み時に定めてデータとともに記録し、各参照にはどの基準で判定したかを記録する
- 見出しと定義の訳文は取り込み時に AI エージェントが作成してリポジトリにコミットし、取り込んだ原文・参照・訳文は運営者がプルリクエストでまとめて査読する
- 各訳文には、どの原文に対応するかを記録する。ビルド時にはリポジトリ内の中間形式データを検証し、形式の誤り・存在しない参照先・原文と一致しない根拠の位置・訳文の欠落・記録された原文が現在の原文と異なる古い訳文があればビルドを失敗させる (外部の原典の更新監視ではなく、リポジトリ内データの整合性を検証する)
- 用語集をまたぐ参照を将来追加できるデータ構造にする
- 見出しが変わらない限り、データを更新しても用語の URL が変わらないようにする
- 同じデータと同じ URL からは、常に同じ用語群の分類とノードの配置を再現できるようにする
- ビルド時および閲覧時に、LLM の API を呼ばない
- PC 上の最新バージョンのブラウザーで、約 2,000 語・約 10,000 件の参照を持つ用語集を全体グラフで表示し、拡大・縮小・平行移動・選択を円滑に行えるようにする。また、クラスタリングと配置の計算中も他の UI 操作を妨げないようにする。初回表示までの時間・操作時の応答性・計算時間の具体的な目標値は、設計段階で定めて記録する
- 対応環境は最新バージョンの Chrome・Firefox・Safari とする。スマートフォンの狭い画面では、検索・定義の閲覧・参照の確認・周辺グラフを利用できることとし、全体グラフの操作は必須としない
- グラフの操作を除く画面全体で WCAG 2.1 AA を満たし、キーボードのみの操作で用語の検索・定義の閲覧・参照の確認を完了できるようにする。また、情報の識別を色や図中の位置だけに依存させない
- 原文を HTML としてそのまま描画せず、中間形式が許可する構造だけを描画する。リンクでは `javascript:` などの危険な URL スキームを拒否し、Content Security Policy でスクリプトの読み込み元を自サイトに限る
- 閲覧時は外部の API や CDN を使わず、スクリプト・スタイル・フォント・データをすべて自サイトの配信元から読み込む。サイトは静的サイトとして構成し、GitHub Actions を用いてこのプロジェクトの GitHub Pages に公開する
- UI コンポーネントとレイアウトの実装では、[Modern Web Guidance](https://developer.chrome.com/blog/modern-web-guidance-v1?hl=ja) を参照し、対応ブラウザーで利用できる HTML と CSS の標準機能を優先する (性能要件を満たすためのグラフ描画方式の選定はこの限りでない)
- 画面の文言と訳文は日本語だけとする

## 対象外とする事項

- 他のサイトへの埋め込み用の配布
- 外部の原典に対する更新の自動監視
- 確認履歴と査読状態の記録
- 閲覧者によるブラウザー上での任意の用語集の読み込み
- 用語集をまたぐ参照
