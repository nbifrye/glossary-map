## この文書について

この文書は、用語集を保持する中間形式を定めます。形式は JSON Schema の [glossary.schema.json](../schemas/glossary.schema.json) と [term.schema.json](../schemas/term.schema.json) で定義し、JSON Schema で表せない規則はこの文書で定めます。設計上の判断の理由は [設計書](design.md) を参照してください。

## ファイルの構成

用語集ごとに `glossaries/` の下にディレクトリを作ります。ディレクトリ名は用語集の ID と同じにします。

```text
glossaries/
  <用語集の ID>/
    glossary.json
    terms/
      <スラッグ>.json
```

`glossary.json` には用語集の情報を、`terms/` には用語ごとに 1 つの JSON ファイルを置きます。`terms/` には、用語の JSON ファイル以外を置けません。各ファイルの `$schema` には、JSON Schema のファイルへの相対パスを書けます。

## 用語集

`glossary.json` には、次の項目を記録します。

- `id`: 用語集の ID。小文字の英数字をハイフンでつないだ文字列とする
- `title`: 用語集の名前
- `source`: 原典の書誌情報。名称 (`name`)・バージョン (`version`)・公開日 (`published`)・URL (`url`)・取得日 (`retrieved`) を記録する。日付は `YYYY`・`YYYY-MM`・`YYYY-MM-DD` のいずれかの形式で書く
- `criteria`: 参照と判定する基準の一覧。基準ごとに、ID (`id`) と説明 (`description`) を記録する。基準の ID は、用語集の中で重複させない

## 用語

用語のファイルには、次の項目を記録します。

- `heading`: 見出し。原典の表記のとおりに記録する
- `headingTranslation`: 見出しの訳文 (`text`) と、見出しのハッシュ値 (`sourceHash`)
- `definitions`: 定義の一覧。1 つの見出しに複数の定義が掲載されている場合は、原典の順に並べる
- `references`: 参照の一覧

### 定義

各定義には、次の項目を記録します。

- `location`: 原典の該当箇所。原典の該当箇所を開ける URL (`url`) と、原典内の記載位置 (`label`、例: 章やページ番号) の少なくとも一方を記録する
- `source`: 定義の原文。後述するブロックの配列で表す
- `translation`: 定義の訳文 (`content`) と、原文のハッシュ値 (`sourceHash`)。訳文も、原文と同じくブロックの配列で表す

### 原文と訳文の構造

原文と訳文は、次のブロックとインラインだけを使った木構造で表します。

- 段落 (`paragraph`): インラインの配列 (`children`) を持つ
- リスト (`list`): 番号付きかどうか (`ordered`) と、項目の配列 (`items`) を持つ。各項目はブロックの配列とする
- 文字列 (`text`): 空でない文字列 (`value`) を持つ
- 強調 (`emphasis`): インラインの配列 (`children`) を持つ
- リンク (`link`): URL (`href`) とインラインの配列 (`children`) を持つ

リンクの URL には、`https:` または `http:` の URL か、サイト内の相対 URL だけを使えます。

### 参照

各参照には、次の項目を記録します。

- `definition`: 参照元の定義。`definitions` の 0 から始まる番号で指定する
- `target`: 参照先の用語。用語集の ID (`glossary`) とスラッグ (`term`) の組で指定する。現在は、同じ用語集の用語だけを参照先にできる
- `start`・`end`: 根拠となる表現の原文中の位置
- `text`: 根拠となる表現。原文の `start` から `end` までの文字列と一致させる
- `criterion`: 判定した基準の ID。`glossary.json` の `criteria` にある ID を使う

位置は、定義の原文に含まれる文字列 (`text` の `value`) を、文書の順に区切り文字を入れずに連結した文字列の中で数えます。数える単位は Unicode のコードポイントで、先頭を 0 とします。`end` の位置の文字は範囲に含めません。たとえば、原文が `A ` と、強調された `subscriber` の 2 つの文字列から成る場合、`subscriber` の位置は `start` が 2、`end` が 12 です。

1 つの定義の中で、参照の範囲を重ねることはできません。原文中の参照箇所を、参照先へのリンクとして表示するためです。

## スラッグ

用語のスラッグは、見出しから次の手順で作ります。

1. Unicode の NFKC で正規化する
2. 小文字にする
3. a 〜 z と 0 〜 9 以外の文字の並びを、ハイフン 1 つに置き換える
4. 先頭と末尾のハイフンを取り除く

たとえば、`Authentication Assurance Level (AAL)` のスラッグは `authentication-assurance-level-aal` です。用語のファイル名は、スラッグに `.json` を付けたものにします。スラッグが空になる見出しや、スラッグが同じ用語集の別の用語と重なる見出しは、ファイル名を決められないため、取り込みの段階で解決します。

## ハッシュ値

訳文に記録するハッシュ値は、SHA-256 の値を小文字の 16 進数で表した文字列です。

- 見出しの訳文: 見出しの文字列を UTF-8 で符号化したもののハッシュ値
- 定義の訳文: 定義の原文 (`source`) を次の規則で JSON に変換し、UTF-8 で符号化したもののハッシュ値。オブジェクトのキーを UTF-16 のコード単位の順に並べ、空白を入れない

原文や見出しを修正するとハッシュ値が変わるため、検証で古い訳文として検出されます。訳文を見直したうえで、検証が示すハッシュ値に更新してください。

## 検証

次のコマンドで、`glossaries/` にあるすべての用語集を検証します。`npm run build` も、最初にこの検証を実行します。

```sh
npm run validate
```

検証では、JSON Schema に従っていることに加えて、次の規則を確かめます。問題があれば、ファイルごとに内容を表示し、0 以外の終了コードで終わります。

- 用語集の ID がディレクトリ名と同じで、基準の ID が重複していないこと
- 用語のファイル名が、見出しから作ったスラッグと一致すること
- 見出しと定義の訳文に記録されたハッシュ値が、現在の見出しと原文のハッシュ値と一致すること
- リンクの URL が、使える URL であること
- 参照元の定義・参照先の用語・判定した基準が存在すること
- 参照の位置が原文の範囲内にあり、その位置の文字列が記録された表現と一致すること
- 1 つの定義の中で、参照の範囲が重なっていないこと
