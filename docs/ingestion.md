## この文書について

この文書は、AI エージェントが原典の用語集を [中間形式](data-format.md) に変換し、リポジトリに取り込む手順を定めます。リポジトリには原典の形式ごとの変換処理を置かないため、エージェントは原典ごとに変換の方法を考えて実行します。変換に使ったスクリプトは、リポジトリにコミットしません。

## 取り込みの流れ

取り込みは、次の 2 つのプルリクエストに分けて進めます。

1. 基準の提案: 原典を調べ、参照と判定する基準の案と、数件の用語の取り込み例を提出する
2. 全件の取り込み: 運営者が基準に合意した後で、残りのすべての用語を取り込む

ほかの用語集で合意した基準をそのまま使う場合は、1 を省略できます。

取り込み例の用語は、参照先の用語もすべて取り込み例に含まれるように選びます。参照先の用語がないと、検証に失敗するためです。

## 原典を調べる

変換を始める前に、原典の次の点を調べます。

- 用語集の範囲: 原典のどの章や付録が用語集か
- 書誌情報: 名称・バージョン・公開日・URL。公開日を原典の中で確かめられない場合は、発行元の公式ページで確かめる
- 定義の構造: 1 つの見出しに複数の定義があるか、定義の中で段落・リスト・強調・リンクがどう使われているか、それ以外の構造 (表や図など) があるか
- 参照の印: 用語集の項目へのリンク・強調・「See」のような案内の表現など、原典がほかの用語を指すときに使う印。印のない語句のうち、ほかの用語の見出しと一致するものがどの程度あるかも調べる

## 基準を決める

参照と判定する基準は、用語集ごとに決めて `glossary.json` の `criteria` に記録します。基準の説明は閲覧者にも表示されるため、日本語で書き、原典を知らない人が読んでも同じ判定を再現できるようにします。説明には、次の事項を含めます。

- 対象とする表現 (例: 強調された語句・印のない語句)
- 見出しと一致するとみなす範囲 (例: 大文字と小文字・単数形と複数形・略語の扱い)
- 同じ定義の中に同じ用語を指す表現が複数ある場合に、どれを記録するか
- 候補の範囲が重なる場合に、どれを選ぶか

原典の印に基づく基準と、エージェントが推定する基準 (印のない語句など) は、別の基準に分けます。どの参照を原典が示しているのかを、閲覧者が区別できるようにするためです。

基準の提案のプルリクエストには、用語集の全件に基準を適用した場合の基準ごとの参照の件数と、判断に迷った例 (一致させるかどうか迷った語句や、基準から外した語句) を記載します。

## 変換する

### 見出しと原文

- 見出しは、大文字と小文字や括弧内の略語も含め、原典の表記のとおりに記録する
- 定義の原文は、段落・リスト・強調・リンクだけを使った木構造に変換する。定義にそれ以外の構造がある場合は、取り込みを止めて運営者に相談する
- 原文の連続する空白や改行は空白 1 つにまとめ、段落の先頭と末尾の空白を取り除く。それ以外の文字は、引用符やダッシュも含めて原典のとおりに記録する
- 相対 URL のリンクは、原典のページの URL を基準にした絶対 URL にする
- `location` には、定義を開ける URL を記録する。用語ごとのアンカーがない場合は、用語集の章や付録のアンカーを使う

### 参照

参照は、変換したデータに基準を機械的に適用して求めます。位置を手で数えると誤りやすいため、位置は変換に使うスクリプトで求めます。

### 訳文

- 見出しの訳文は、用語集の中で統一する。定義の訳文でほかの用語の見出しを訳すときは、その用語の見出しの訳文を使う
- 原文で強調されている語句やリンクは、訳文でも対応する箇所を強調またはリンクにする。リンクの URL は、原文と同じにする
- 原文にない説明を補ったり、原文の一部を省いたりしない
- 原典の分野で定着している訳語がある場合は、その訳語を使う

### ハッシュ値

訳文の `sourceHash` には、[ハッシュ値](data-format.md#ハッシュ値) の規則で求めた値を記録します。変換に使うスクリプトで求めるか、仮の値を記録してから `npm run validate` を実行し、検証が示す値に置き換えます。

## 確かめる

`npm run validate` と `npm run check` が成功することを確かめます。全件の取り込みでは、原典の見出しの数と `terms/` のファイルの数が一致することも確かめます。
